# CHUCHU AI STUDIO - Inquiry -> Agreement Field Map

Internal workflow reference. The inquiry captures what the client wants; the Agreement/SOW captures what CHUCHU AI STUDIO actually agrees to build.

## Status legend
- DIRECT TRANSFER: copy after basic verification.
- REVIEW / DERIVE: use as input, but CHUCHU AI STUDIO must draft final contract wording.
- STUDIO / CONFIRM: not supplied by the inquiry; create or confirm before sending.

## Direct transfer
| Inquiry | Agreement / SOW | Rule |
|---|---|---|
| Your name | CLIENT - Authorized Representative | Copy. If individual client, may also be Company / Individual. |
| Company / organization | CLIENT - Company / Individual | Copy. If blank, use the individual client name. |
| Role / job title | CLIENT - Job Title | Copy. |
| Email | CLIENT - Email | Copy and verify. |
| Phone / WhatsApp | CLIENT - Phone | Copy if supplied. |
| Selected service type | Schedule A - Project Type | Copy then confirm after scope review. |
| Target platforms | Schedule A - Platforms | Copy only platforms included in final scope. |
| Preferred first usable / launch date | Schedule A - Estimated Delivery Date | Treat as client target; replace with Studio-approved estimate. |

## Review / derive
| Inquiry information | Agreement / SOW | Rule |
|---|---|---|
| What to build + problem + users | Project Objective | Rewrite professionally and concisely. |
| Feature checklist + 3 must-haves | Included Features | Finalize v1 after Studio review. |
| Requested items deferred from v1 | Excluded / Future Features | Explicitly list to protect scope. |
| Existing assets | Additional Terms / Client Responsibilities | Identify assets, accounts, APIs, content, credentials client must provide. |
| AI / technical requirements | Included Features + Additional Terms | Convert only after technical review. |
| Sensitive/confidential info | Additional Terms / privacy-security notes | Flag requirements; do not invent legal compliance promises. |
| Success criteria | Objective / acceptance / Additional Terms | Convert to testable outcomes where possible. |
| Additional notes/references | Scope or Additional Terms | Context only unless intentionally incorporated. |
| Decision-maker | Authorized Representative only if confirmed | Otherwise internal contact note. |
| Preferred communication | Internal note | Usually not a contract field. |

## Studio / confirm
- Agreement No.: generate internally.
- Effective Date: set when ready for signature.
- Jurisdiction: choose deliberately.
- Studio legal entity/proprietor and registered address: use confirmed legal details.
- Client registered address: request separately; not in current inquiry form.
- Project Name: create from client/product concept.
- Deliverables: Studio-drafted from approved scope.
- Estimated Start Date: depends on signature, deposit, client readiness, and Studio capacity.
- Total Project Fee: Studio quotation after scope review. Never treat budget range as fee.
- Payment Currency: confirm quoted currency.
- Additional Terms: project-specific Studio-authored terms.

## Payment milestones
- 30% Commencement Deposit = Total Fee x 0.30
- 30% Development Milestone = Total Fee x 0.30
- 25% Beta / Acceptance Testing = Total Fee x 0.25
- 15% Final Acceptance / Handover = Total Fee x 0.15

## Workflow
1. Website lead arrives.
2. Send Project Inquiry & Discovery Form.
3. Client returns completed inquiry.
4. CHUCHU AI STUDIO reviews scope.
5. Pre-fill Agreement + Schedule A.
6. Internal QA.
7. Send completed Agreement for client review/signature.
8. Client returns signed Agreement + proof of 30% deposit.
9. Begin development after payment confirmation and required access/assets are available.

## Automation guardrails
Future automation may pre-fill and draft, but must not:
- auto-sign;
- treat the client's budget range as the project fee;
- silently put every requested feature into contractual scope;
- invent missing legal/registered-address information;
- infer signatory authority without confirmation.
